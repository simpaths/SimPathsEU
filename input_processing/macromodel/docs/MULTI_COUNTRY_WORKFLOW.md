# Multi-Country DSGE Model Workflow

## Overview

This document describes the workflow for creating country-specific DSGE models for SimPaths integration. The German model serves as the template; other countries (Spain, Poland, UK, Sweden) follow the same structure with country-specific calibration and estimation.

## Model File Architecture (Refactored)

The DSGE model uses a **template + wrapper** pattern for multi-country support:

```
input_processing/macromodel/
  Macromodel_template.mod              ← Shared structural equations (DO NOT RUN DIRECTLY)
  Macromodel_Germany.mod               ← Thin wrapper: @#define country = "Germany" + @#include
  Macromodel_Poland.mod                ← Thin wrapper: @#define country = "Poland" + @#include
  Macromodel_Spain.mod                 ← Thin wrapper: @#define country = "Spain" + @#include
  Macromodel_Sweden.mod                ← Thin wrapper: @#define country = "Sweden" + @#include
  Macromodel_[COUNTRY]_frozen.mod      ← Auto-generated by generate_frozen_model.m
  country_params/
    Germany_calibration.mod            ← Parameter values, steady-state ratios
    Germany_estimation.mod             ← Shocks, priors, measurement errors, datafile
    Poland_calibration.mod
    Poland_estimation.mod
    Spain_calibration.mod
    Spain_estimation.mod
    Sweden_calibration.mod
    Sweden_estimation.mod
```

**Adding a new country** requires creating 3 files:
1. `country_params/{Country}_calibration.mod` — parameter values
2. `country_params/{Country}_estimation.mod` — shocks, priors, data config
3. `Macromodel_{Country}.mod` — 2-line wrapper

| File | Purpose |
|------|---------|
| `Macromodel_[COUNTRY].mod` | Wrapper → estimation (runs Dynare as before) |
| `Macromodel_[COUNTRY]_frozen.mod` | Simulation (auto-generated, posterior modes hardcoded) |

## Parameter Classification

### Tier 1: Universal (Fixed Across All Countries)

These are "deep" parameters with strong theoretical foundations:

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| `beta` | 0.99 | Quarterly discount factor (~4% annual) |
| `sigma` | 1.0 | Log utility (standard) |
| `alpha_m` | 0.5 | Matching function elasticity (Petrongolo & Pissarides 2001) |
| `eta` | 0.5 | Hosios efficiency condition |

### Tier 2: Country-Specific Calibration (From Data/Literature)

These vary by country but are calibrated, not estimated:

| Parameter | Description | Source | Notes |
|-----------|-------------|--------|-------|
| `chi_L` | Labor force share, L/WAP | Eurostat LFS | Age 15-64, estimation-sample mean |
| `chi_u` | Unemployment **share**, U/WAP | `chi_L` × sample-mean ILO rate | **Not** the U/L rate |
| `chi_n` | Total employment share, N/WAP | Derived: `chi_L - chi_u` | Total employment, not employees |

> **Calibrate `chi_L` and `chi_u`; derive `chi_n`. Never the other way round.**
> The identity (eq. 10) requires `chi_u = chi_L - chi_n`, but `chi_L` and `chi_n`
> are two large, similar numbers, so computing `chi_u` as their difference
> amplifies any rounding by more than an order of magnitude. Rounding Poland's
> `chi_n` from 0.6777 to 0.70 turned `chi_u` from 0.052 into 0.030 — a 43% error
> in the coefficient scaling the whole latent u channel, worth ~156 log points of
> marginal likelihood. Deriving `chi_n` from `chi_u` keeps errors proportional.
>
> **Use the estimation-sample mean unemployment rate, not a recent window.** The
> model is linearised around the sample it is estimated on. Poland 2005-2025
> averages 7.16% (range 2.7-18.3%); the 2018-2023 window alone gives 4.1%.
> `test_calibration_identities.m` checks both the identity and that the implied
> rate matches the sample.
>
> **Two errors nearly cancelled historically.** Poland's original `chi_u = 0.05`
> was entered as the U/L rate (too big by ~1/`chi_L`) on a low-unemployment window
> (too small by ~1.75x), landing close to the correct 0.0523 by accident.
| `delta` | Separation rate | OECD EPL data | Higher for flexible markets |
| `lambda_w` | Wage stickiness | Institutional | Collective bargaining coverage |
| `phi_pi`, `phi_y` | Taylor rule | Literature | ECB for €-zone, BoE for UK, Riksbank for Sweden |

**Country-specific values:**

| Parameter | Germany | Poland | Spain | Sweden | UK |
|-----------|---------|--------|-------|--------|-----|
| `chi_L` | 0.77 | 0.73 | 0.74 | 0.81 | 0.78 |
| sample-mean U/L rate | 5.44% | 7.16% | 15.37% | 7.27% | ~5% |
| `chi_u` = `chi_L`×rate | 0.0419 | 0.0523 | 0.1137 | 0.0589 | 0.039 |
| `chi_n` = `chi_L`−`chi_u` (derived) | 0.7281 | 0.6777 | 0.6263 | 0.7511 | 0.741 |
| `delta` | 0.025 | 0.035 | 0.040 | 0.030 | 0.045 |
| `lambda_w` | 0.75 | 0.65 | 0.70 | 0.75 | 0.60 |

*Germany, Poland, Spain and Sweden are computed from their own estimation samples
(`data_for_dynare_levels_{COUNTRY}.csv`, `u_level` column). UK is an illustrative
placeholder and is not implemented — compute the sample-mean rate from its own
data before using it.*

**Caveat on `chi_n`.** The observable feeding `n` is employees *excluding
self-employed* (Poland: 0.5412 of WAP), while `chi_n` above is the *total*
employment share (0.6777). The identity needs total employment, so using it here
assumes self-employment moves proportionally with employees — which keeps the
identity's coefficient difference at exactly 1. In Poland self-employment is 20%
of employment, so this assumption is doing real work and should be revisited if
the search-and-matching block is ever taken literally as a model of employee jobs.

### Tier 3: Estimated from Country Data

Only `omega_h` and the shock standard deviations are estimated; every structural
parameter is fixed at its calibrated value because the identification problems are
structural rather than data-specific. The country estimation file is the authority —
the Poland priors below are illustrative of the shape, not a second copy to maintain.

| Parameter | Prior (Poland) | Description |
|-----------|----------------|-------------|
| `omega_h` | Beta(0.35, 0.10) | Hours weight in production |
| `stderr eps_a` | InvGamma(0.50, 0.25) | Technology shock |
| `stderr eps_d` | InvGamma(0.50, 0.25) | Demand shock |
| `stderr eps_r` | InvGamma(0.40, 0.15) | Monetary shock |
| `stderr eps_p` | InvGamma(0.70, 0.30) | Cost-push shock |
| `stderr eps_L` | InvGamma(0.15, 0.06) | Labour force shock |
| `stderr eps_h` | InvGamma(0.35, 0.10) | Hours shock |
| `stderr eps_inv` | InvGamma(0.60, 0.25) | Investment shock |

## Data Requirements per Country

### Observables (8 time series, quarterly)

`varobs` in `Macromodel_template.mod` is the authority: `y inv c pi R n L h`.

| Variable | Description | Source |
|----------|-------------|--------|
| `y` | Real GDP | National accounts |
| `inv` | Gross fixed capital formation | National accounts |
| `c` | Household final consumption | National accounts |
| `pi` | Inflation (HICP, QoQ annualised) | Eurostat |
| `R` | Short-term interest rate | Central bank |
| `n` | Employees, national concept | Labour force survey |
| `L` | Labour force, national concept | Labour force survey |
| `h` | Hours per employee | Labour force survey |

All eight are supplied as **Ramsey-detrended** 100×log-deviations by `ramsey_trend.m`,
not as HP-filtered cycles. `R` and `pi` are rate variables and enter as demeaned
percent. The HP-filtered file (`data_for_dynare_hp_{COUNTRY}.csv`) exists only as a
benchmark for `run_detrending_benchmark.m` and is not the estimation input.

### Sample Period

Set in `{Country}_estimation.mod` and bounded by `startdate`/`enddate` in
`make_datasets.do`. Germany starts 2000q1 (EMU), Poland 2005q1 (data availability
after EU accession), Spain 2000q1 (matching Germany; Spain is a 1999 euro founder,
but the OECD LFS stocks only begin 1999q1 and 2000q1 leaves them a year of
burn-in), Sweden 2001q1 (a pure data constraint — the OECD LFS stocks begin
2001q1, which happens to sit well inside the inflation-targeting regime adopted
in 1993, so the sample is one monetary regime). COVID (2020q1-2021q2) is censored
to missing in the estimation file; Dynare's Kalman filter handles the gap.

### Currency: euro volumes, national-currency wages

Two rules, for any country with its own currency:

- **Chain-linked volumes may be in euro.** Eurostat's `CLV15_MEUR` is
  `CLV15_MNAC` converted at the *fixed 2015* exchange rate, a constant rescaling
  (0.10691 for SEK) that drops out of every ratio and log deviation the Ramsey
  and DSGE layers use. All four countries' volumes are therefore in euro and
  `K_0`, `Y_0` are comparable in level terms.
- **Current-price wage aggregates must be in the currency of the price index
  that deflates them.** Eurostat converts `CP_MEUR` at the *current* exchange
  rate. `real_wage_per_employee` divides by the domestic HICP, so a euro
  numerator puts every exchange-rate swing into the "real" wage. For Sweden the
  implied conversion factor runs from 0.085 to 0.119 over 2001-2025. Sweden's
  D1/D11 are therefore `CP_MNAC`, and `w_level` is the one Swedish level series
  in SEK.

Poland does not follow the second rule yet: its D1/D11 are `CP_MEUR` against a
PLN-denominated HICP, so `w_level` for Poland carries PLN/EUR movements. This is
harmless for the model (`w` is not in `varobs`, and no MATLAB stage reads
`w_level`), but the column is not a clean real wage. Switch it to `CP_MNAC` at
the next Poland data refresh.

### Interest rate

`R` is the monthly average of the last month of the quarter for every country:
ECB Euribor for Germany and Spain, Eurostat `irt_st_m` for Poland (WIBOR) and
Sweden. Poland used OECD MEI `POL.IR3TIB01.ST.M` until 2026-10; that dataset
stopped at 2024-01 and was an end-of-month value, so it is not interchangeable
with the Eurostat series and must not be spliced onto it.

### Data Preparation

Extend the Stata script `make_datasets.do` with a country branch. For each country:
1. Add a `series_codes_q` block with that country's dbnomics provider/dataset/series IDs
2. Map them onto the internal variable names the rename block expects
3. Set `startdate`/`enddate`
4. Add the HICP series to the seasonal-adjustment program if it is not already there

## Workflow: Creating a New Country Model

### Step 1: Add the country to the data pipeline

Add the country branch to `stata/make_datasets.do` (see above) and run it from
`input_processing/macromodel/stata/`. It writes `input_processing/macromodel/data/data_for_dynare_levels_{COUNTRY}.csv`,
which is the input to the Ramsey layer.

### Step 2: Create the growth-model parameter file

```
country_params/{Country}_growth_params.json
```

Copy `Poland_growth_params.json` and set the structural inputs: `alpha_K`, `sigma`,
`phi`, `delta_annual`, `beta_annual`, `base_year`, `tfp_growth_annual`, the
`terminal_growth` block, and the inflation target. `base_year` **must** equal the
year of the first row of the levels CSV — `ramsey_trend.m` asserts this.

### Step 3: Create the DSGE country files

```
country_params/{Country}_calibration.mod   # parameter values
country_params/{Country}_estimation.mod    # priors, shocks, datafile
Macromodel_{Country}.mod                   # 2-line wrapper
```

Calibrate `chi_L` and `chi_u` from that country's own sample and **derive** `chi_n`
(see the Tier 2 warning above). `test_calibration_identities.m` will fail loudly if
the triple is inconsistent or the implied rate does not match the estimation sample.

There is no static model. Static artefacts (`*_static.mod`, `generate_static_model.m`,
`export_static_for_simpaths.m`, `static_M.csv`) were removed from the pipeline; do not
recreate them.

### Step 4: Run the full workflow

```matlab
>> run_full_workflow('Spain')
```

This executes, in order:
1. Ramsey growth-model calibration (`calibrate_growth_model`)
2. Ramsey trend solve and detrending (`ramsey_trend`)
3. SimPaths-aligned population projection (`build_population_projection`)
4. Bayesian estimation (Dynare)
5. Frozen-model generation (`generate_frozen_model`)
6. Dynamic policy-matrix export for SimPaths (`export_dynamic_for_simpaths`)
7. Postestimation analysis and summary report

Note the ordering caveat in `docs/Integration_Contracts.md`: step 3 writes the
demographic tail that step 2 consumes, so a *changed demographic projection* needs a
second run to propagate fully.

Optional example (skip postestimation):

```matlab
>> run_full_workflow('Spain', 'skip_postestimation', true)
```

## Consistency Verification

After generating models for all countries, verify:

### 1. Parameter Plausibility

Check that estimated parameters are in reasonable ranges:
- `rho_h` ∈ [0.6, 0.95] (hours persistence)
- `psi_hy` ∈ [0.01, 0.10] (hours-demand elasticity)
- `omega_h` ∈ [0.2, 0.5] (hours weight)

### 2. Cross-Country Comparisons

Expected patterns:
- Higher `delta` (separation rate) for UK, Spain (flexible markets)
- Higher `lambda_w` (wage stickiness) for Germany, Sweden (collective bargaining)
- Higher `psi_hy` for Germany (Kurzarbeit) than UK

### 3. Policy-Matrix Sign Verification

For all countries, verify the impact (t=0) responses in the exported bundle
(`irfs_eps_L.csv`, `irfs_eps_h.csv`):
- L↑ → w↓ (labour supply increase reduces wages)
- L↑ → π↓ (disinflation from the wage channel)
- h↑ → w↑ (hours increase **raises** the wage). `w` is compensation per
  *employee*, and hours per employee raise the per-worker marginal product the
  reset wage bargains over: in `Macromodel_template.mod`,
  ∂`w_star`/∂`h` = (1 − β·`lambda_w`)·`eta`·`alpha_n`·`omega_h` > 0 for any
  admissible calibration. A negative response here would indicate an export
  bug, not the expected pattern.
- h↑ → π↓ (marginal cost falls: the marginal product rises at once, the
  staggered wage only partly)

All four patterns hold in all four country bundles (checked 2026-10). Earlier
versions of this list expected h↑ → w↓, which the model cannot produce by
construction.

Remember that the exported matrices hold **raw `ghu`** entries: a one-standard-deviation
response is `ghu(y, eps_j) * sigma_j` (multiply, never divide), while `eps_L` and `eps_h`
from SimPaths are percent log-deviations and are not sigma-scaled. See contracts #1 and #3
in `docs/Integration_Contracts.md`.

## Troubleshooting

### Common Issues

1. **Estimation fails to converge**
   - Check data for outliers (especially COVID period)
   - Try different mode_compute option (4, 6, or 9)
   - Verify priors are not too tight

2. **Blanchard-Kahn conditions violated**
   - Check Taylor rule satisfies Taylor principle (φ_π > 1)
   - Verify discount factor β < 1
   - Check for typos in parameter values

3. **M matrix has wrong signs**
   - Verify vacancy equation uses structural form: v = -(1 + β*λ_w)*w
   - Check that labor market equilibrium is correctly specified

4. **Cross-country parameter differences seem implausible**
   - Review data sources for consistency
   - Check seasonal adjustment methods match
   - Verify sample periods are comparable

Each country model should be tracked separately in Git:
- Commit estimation results after successful runs
